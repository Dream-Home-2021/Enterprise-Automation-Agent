你的 DATAGEN 项目本质上是一个 多 Agent 协作系统：
        用户提问 → Router → SearchAgent → HypothesisAgent → ... → ReportAgent → 输出
        问题来了
        假设用户说"结果不对"，你去看日志文件 agent.log，发现：


        2026-06-25 10:30:01 - src - INFO - Received query
        2026-06-25 10:30:02 - src - INFO - Searching...
        2026-06-25 10:30:05 - src - INFO - Generating hypothesis...
        2026-06-25 10:30:06 - src - ERROR - Timeout
        2026-06-25 10:30:10 - src - INFO - Another query received
        2026-06-25 10:30:11 - src - INFO - Searching...
        两个问题一下子暴露了：

        "Timeout" 是哪个请求的？ 第一个还是第二个？分不清
        "Searching" 是谁发的？ SearchAgent？还是别的？也分不清
        第一步：子 Logger（解决"谁发的"）
        就是你之前问的——不要都用 "src"：


        # 现在：所有人都是 src，分不清
        logger = setup_logger()  # → logging.getLogger("src")

        # 改成：各自带名字
        # search_agent.py
        logger = logging.getLogger("src.agents.search")
        # router.py  
        logger = logging.getLogger("src.router")
        日志就变成了：


        10:30:02 - src.agents.search  - INFO - Searching...
        10:30:06 - src.agents.hypothesis - ERROR - Timeout
        一眼就知道是谁报的错。 这一步你现在就能改。

第二步：Trace ID（解决"哪次请求的"）
        想象你开了一家餐厅：

        客人 A 点了宫保鸡丁，客人 B 点了鱼香肉丝
        后厨的出单机只打印菜名，不写桌号
        菜做好了，服务员端给谁？
        桌号 = Trace ID。每条日志都要带上它。


        import contextvars

        # 定义一个"当前桌号"的容器
        current_trace_id = contextvars.ContextVar("trace_id", default="no-trace")

        # 在请求入口生成一个
        import uuid
        current_trace_id.set(str(uuid.uuid4())[:8])  # 比如 "a3f1b2c0"

        # 每条日志自动带上
        10:30:02 - src.agents.search  - INFO - [a3f1b2c0] Searching...
        10:30:06 - src.agents.hypothesis - ERROR - [a3f1b2c0] Timeout
        10:30:10 - src.agents.search  - INFO - [e7d94512] Searching...   ← 这是另一个请求
        搜 a3f1b2c0，这条请求从头到尾的日志全出来了。

        对你项目来说：如果同一时间只处理一个请求，暂时还用不上。但如果将来支持并发（多个用户同时提问），这就是必需的。

第三步：日志轮转（解决"磁盘爆了"）
        这个最简单——日志文件不能无限增长：


        # 现在：写到一个文件，永远追加
        file_handler = logging.FileHandler('agent.log')

        # 改成：单文件最大 50MB，最多保留 5 个旧文件
        from logging.handlers import RotatingFileHandler
        file_handler = RotatingFileHandler(
            'agent.log', 
            maxBytes=50*1024*1024,  # 50MB
            backupCount=5,           # agent.log.1, .2, .3, .4, .5
            encoding='utf-8'
        )
        磁盘最多占 50MB × 6 = 300MB，永远不会爆。这一步你现在就该改。

第四步再往下：日志集中收集
        就是刚才你说看不懂的部分。核心概念其实很简单：

        不要 SSH 上服务器去看文件。

        类比：

        现在：日志写在本地文件 → 相当于每个人把笔记记在自己本子上
        ELK：所有日志汇到一个地方 → 相当于所有人把笔记交到档案室，有管理员帮你查

        你的服务器                    日志平台（比如 Kibana 网页）
        ┌───────────┐               ┌──────────────────────────────┐
        │ agent.log │─── Filebeat ──→│ 搜索: trace_id = a3f1b2c0    │
        │           │   (自动搬运工)  │ 结果: 这条请求的所有日志全出来  │
        └───────────┘               └──────────────────────────────┘
        什么时候需要？ 你只有 1 台服务器、1 个自己用 → 不需要。你有 10 台服务器、团队协作 → 才需要。

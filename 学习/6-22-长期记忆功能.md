```python
async def start_background_extractor():
    async def _loop():
        interval = _CONFIG["interval_mins"] * 60  # 默认 15 分钟
        while True:
            await asyncio.sleep(interval)
            await batch_process_pending(_CONFIG["interval_mins"])
    _background_task = asyncio.create_task(_loop())
```
<!-- 评估价值（Value Filtering）： 系统首先评估这句话是否值得作为“长期记忆”。如果这只是用户无意义的刷屏，系统直接抛弃，仅保留在 Redis 的短期 Checkpoint（上下文历史）中，过了 TTL 自动自动销毁。

提取事实（Fact Extraction）： 如果通过评估，LLM 会尝试从中榨取“KV 事实”。显然，这句话会无功而返，Summary 轨写入失败（或者返回空）。

向量压缩（Vector Indexing）： 系统将整段文字（连同它发生的时间、当时的前后上下文）转化为高维向量，追加存入 Vector DB。

定期归并（Consolidation / Scheduled Cron Job）： 生产环境在深夜跑批时，可能会把最近一周所有类似的乱七八糟的向量碎片拿出来，让大模型做一次“记忆压缩”（例如：“该用户喜欢用天马行空的动作做比喻”），把这个压缩后的新标签反哺写入 Summary 轨，并清理掉低价值的原始向量。 -->
→ `agent/memory/profile.py:103-153` — 批量处理
```python
async def batch_process_pending(interval_mins: int = 15):
    """批量处理待办会话的摘要生成 + 向量化存储"""
    sessions = await get_pending_sessions(interval_mins)
    for sess in sessions:
        messages = await load_conversation_history(session_id)  # 读 Redis checkpoint
        summary_result = await generate_summary(messages)       # LLM 摘要
        await db.save_summary(...)                              → agent_conversation_summaries
        await _save_vectors_async(...)                          → agent_memory_vectors
```

→ `agent/memory/profile.py:84-99` — 查询待办会话
```python
async def get_pending_sessions(interval_mins=15):
    """条件: message_count > 0 AND updated_at < 30分钟 AND 无对应摘要"""
    SELECT s.id, s.user_id, s.message_count
    FROM agent_sessions s
    WHERE s.message_count > 0
      AND s.updated_at >= NOW() - INTERVAL '30 minutes'
      AND NOT EXISTS (SELECT 1 FROM agent_conversation_summaries cs
                      WHERE cs.session_id = s.id)
```

**流程图：**
```
start_background_extractor()
  └→ asyncio.create_task(_loop)  ← 每 15 分钟
       └─ batch_process_pending()
            ├─ get_pending_sessions()   ← SQL 查待办（含幂等性 NOT EXISTS）
            ├─ load_conversation_history()  ← 读 Redis checkpoint
            ├─ generate_summary()       →  agent_conversation_summaries
            └─ _save_vectors_async()    →  agent_memory_vectors
```

## 3. 语义 vs 非语义 + 向量 RAG 检索

### 架构设计

| 类型 | 表 | 提取 | 检索 |
|------|-----|------|------|
| **非语义** | `agent_user_preferences` | LLM 提取偏好 KV | SQL：`WHERE user_id=$1 AND key=$2` |
| **非语义** | `agent_user_profile` | LLM 合并画像 JSONB | SQL：`WHERE user_id=$1` |
| **非语义** | `agent_conversation_summaries` | LLM 生成摘要 + tags | SQL：`ORDER BY created_at DESC LIMIT 5` |
| **语义** | `agent_memory_vectors` | Embedding API 向量化(1536d) | HNSW 余弦相似度 Top-K |

### RAG 检索代码

`agent/memory/long_term.py:95-147` — 向量记忆检索函数
```python
async def load_relevant_memories(
    user_id: int, query: str, top_k: int = 5
) -> str:
    """根据用户查询，从向量记忆中检索最相关的历史记录。"""
    query_embedding = await _get_embedding(query)  # Embedding API
    if not query_embedding:
        return ""

    results = await db.search_memory_vectors(
        user_id=user_id,
        query_embedding=query_embedding,
        top_k=top_k,
    )
    # 格式化为"=== 相关历史记忆 ==="文本块
    parts = ["=== 相关历史记忆 ==="]
    for r in results:
        score = r.get("score", 0)
        content = r.get("content", "")[:200]
        parts.append(f"- [{score:.2f}] {content}")
    return "\n".join(parts)
```

`agent/memory/long_term.py:150-166` — Embedding 封装
```python
async def _get_embedding(text: str) -> list[float] | None:
    """用 OpenAI embedding API 生成文本向量。"""
    client = OpenAI(api_key=..., base_url=...)
    response = client.embeddings.create(
        model="text-embedding-v3",
        input=text[:500],
    )
    return response.data[0].embedding
```

`agent/supervisor/graph.py:57-75` — Supervisor 节点中注入 RAG
```python
if _MEMORY_VECTOR_TOP_K > 0 and state.get("messages"):
    last_msg = state["messages"][-1]
    query_text = getattr(last_msg, "content", None) or ...
    if query_text and isinstance(query_text, str):
        relevant = await load_relevant_memories(
            user_id=user_id, query=query_text, top_k=_MEMORY_VECTOR_TOP_K,
```

```python
async def search_memory_vectors(user_id, query_embedding, top_k=5):

        SELECT content, metadata, 1 - (embedding <=> $1::vector) AS score, created_at
        FROM agent_memory_vectors
        WHERE user_id = $2
```

## 5. 错误隔离

| 位置 | 代码 | 错误发生时 |
|------|------|-----------|
| `router.py:235` | `except Exception as e: logger.warning(...)` | 只打印日志，不影响 SSE 流和 done 事件 |
| `chat_agent.py:47-51` | `except Exception as e: logger.warning(...)` | 画像加载失败不影响 chat_agent 正常对话 |
| `supervisor/graph.py:72-74` | `except Exception as e: logger.warning(...)` | RAG 检索失败不影响 supervisor 路由判断 |
| `profile.py:61-69` | `except Exception as e: logger.warning(...)` | 偏好提取失败不影响 batch 中其他会话处理 |
| `profile.py:137-143` | `except Exception as e: logger.warning(...)` | 单个会话批量提取失败不影响其他待办会话 |
| `profile.py:147-152` | `except Exception as e: logger.warning(...)` | 向量化失败跳过，不做任何影响 |
| `long_term.py:133-136` | `except Exception as e: logger.warning(...)` | 向量搜索失败返回空字符串，不抛异常 |
| `long_term.py:163-165` | `except Exception as e: logger.warning(...)` | Embedding 生成失败返回 None，上游自动跳过 |

**原则：** 记忆系统的任何异常都不会传播到用户响应路径。最坏情况 = 没有记忆，对话照常进行。

## 6. 幂等性

| 操作 | 保障机制 | 文件位置 |
|------|---------|---------|
| 偏好写入 | `ON CONFLICT (user_id, key) DO UPDATE` | `postgres.py:278-285` |
| 画像写入 | `ON CONFLICT (user_id) DO UPDATE` | `postgres.py:386-400` |
| 摘要写入 | `summary_exists_for_session()` SQL 检查 + `NOT EXISTS` 子查询 | `postgres.py:363-371` + `profile.py:85` |

偏好和画像使用 PostgreSQL UPSERT 语法：
```sql
INSERT INTO agent_user_preferences (user_id, key, value, ...)
VALUES ($1, $2, $3, ...)
ON CONFLICT (user_id, key)
DO UPDATE SET value = EXCLUDED.value, ...;
```
同一个 `user_id + key` 组合只会有一个记录，重复执行就是覆盖，不会产生重复行。

批量提取待办会话的幂等性（`profile.py:85`）：
```sql
NOT EXISTS (SELECT 1 FROM agent_conversation_summaries cs WHERE cs.session_id = s.id)
```
已有摘要的会话不会被重复处理。
